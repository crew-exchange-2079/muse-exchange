# T3 Code: can it drive Claude Code, Codex and Gemini from one place on Linux — and does it beat running each CLI separately?

**Short answer:** Yes, mostly. T3 Code is a free, MIT-licensed control surface that drives Claude Code and Codex through the CLIs and subscriptions you already have, on Linux, from one desktop/web/phone interface, with per-thread git worktrees, a diff/PR review flow, remote access, and a scriptable `t3` CLI. Gemini is the gap: Gemini CLI is **not** a named first-class provider — Google's consumer path for it is Antigravity, which T3 Code *does* support, and Gemini CLI itself speaks ACP natively, so it should be reachable through T3 Code's "any ACP agent" support, but I did not verify that end to end. For someone already running Claude Code + Codex headless on Linux behind a scheduler, T3 Code does **not** beat the bare CLIs for unattended scheduled work — it wins for interactive supervision, remote approval from a phone, and handing work between agents. Recommendation: **try, don't adopt wholesale** (see §5).

All facts below were read from public web pages on 2026-11-17 (EST). Every fact carries its source link; anything I could not verify is marked **unsure** / NOT FOUND.

## 1. What T3 Code is today

- **What it is:** an open-source "control plane" / "agent harness control surface" for coding agents. It is **not** an agent and **not** a model: a local server on your machine starts the provider CLIs you already have installed and turns their different event streams into one chat interface. Quote from the project README: "T3 Code runs the coding agents on your machine and gives them one fast interface. Start a thread at your desk, then approve the next step from your phone." — https://github.com/pingdotgg/t3code (read 2026-11-17)
- **Who makes it:** T3 Tools / Ping Labs — Theo Browne and Julius Marminge's team, the people behind the T3 Stack and T3 Chat. — https://flaviocopes.com/t3-code/ (read 2026-11-17); https://www.myargoquest.com/blog/t3code-explained (read 2026-11-17)
- **Licence:** MIT. — https://github.com/pingdotgg/t3code (read 2026-11-17)
- **Price:** free; the project's own FAQ says "There's no way to pay us to use T3 Code." You still pay your model providers. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)
- **Platforms:** macOS, Windows, Linux; plus a web app (app.t3.codes), iOS and Android apps, and a `t3` command-line server. Linux install paths documented: `.deb` for Debian/Ubuntu, `yay -S t3code-bin` on Arch, `nix profile add github:NixOS/nixpkgs/nixos-unstable#t3code`, or `curl -fsSL https://t3.codes/install.sh | sh` for the CLI. — https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17)
- **Maturity:** very early and fast-moving. The README says "We are very very early in this project. Expect bugs." Latest stable release reported as v0.1.9, 2026-11-11; the desktop app is labelled Beta. Repo created 2026-02-08; 64,302 stars and 11,321 forks as shown on the repo page on 2026-11-17; 12,224 commits. — https://github.com/pingdotgg/t3code (read 2026-11-17); https://flaviocopes.com/t3-code/ (read 2026-11-17)
- **Scale claim, unverified:** the repo's own AGENTS.md mentions 500,000 users; that is the project's own claim, not independently verified. — https://codebridge-ai.com/en/blog/t3-code-multi-agent-control-surface/ (read 2026-11-17)
- **Remote relay (T3 Connect):** free for up to 3 machines per account; a paid T3 Chat plan raises it to 10 machines (Pro) or 100 (Premier). LAN pairing and Tailscale work with no account. Your code and prompts go from your machine to your provider, not to T3 servers; with T3 Connect, traffic rides a Cloudflare tunnel. T3 Code does send basic product usage events (provider, model, token totals — no prompts, no file contents) unless you set `T3CODE_TELEMETRY_ENABLED=false`. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)

## 2. Which agents it drives, and how

**Mechanism — official CLIs, not API keys (by default).** T3 Code drives each agent's own installed CLI/SDK on the host machine. You log in to each provider's own CLI first, then T3 Code drives that session. It does not resell tokens and adds no usage quota of its own. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17); https://www.developersdigest.tech/blog/t3-code-open-source-gui-claude-code-codex-opencode-2026 (read 2026-11-17)

| Agent | How T3 Code drives it | Subscription works? |
|---|---|---|
| Claude Code | Anthropic Agent SDK / installed `claude` CLI; `claude auth login` | Yes — Claude Pro/Max subscription works; FAQ: "Can I use T3 Code with my Claude Code subscription? Yes." |
| Codex | Installed Codex CLI, `codex login`, or connect with ChatGPT from provider settings | Yes — ChatGPT Plus/Pro subscription works |
| Cursor | Cursor CLI (`cursor-agent`), `agent login` | Yes, via Cursor's own login |
| Grok Build | Grok Build CLI, `grok login` | Yes, via its own login |
| OpenCode | Installed OpenCode, `opencode auth login` | Yes, via its own login |
| Google Antigravity | No CLI needed; enable in Settings, sign in with Google | Yes |
| Kiro | Kiro CLI, `kiro-cli login` | Yes, via its own login |
| Pi | Pi with Node.js 22.19+, `pi` then `/login` | Yes, via its own login |
| Muse Code | Install on server, `muse login` | Yes, via its own login |
| fx | Install fx, `fx login` | Yes, via its own login |
| Any ACP agent | Agent Client Protocol registry agents | Depends on the agent |

Sources for the table: https://github.com/pingdotgg/t3code (read 2026-11-17); https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17); https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17).

**API keys / OpenRouter instead of a subscription:** also possible. The FAQ: "Add another provider instance in Settings and give it its own keys and endpoint. Claude has a full OpenRouter recipe. Your subscription setup stays untouched." Multiple instances per provider (separate accounts/configs, own env vars/API keys/base URL) are supported. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17); https://aicodewith.ai/en/blog/t3-code-claude-code-codex-setup (read 2026-11-17)

**Claude usage-limit caveat (now fixed):** T3 Code drives Claude through Anthropic's Agent SDK, and the 5-hour meter used to charge Agent SDK usage ~1.7x more than Claude Code directly. Per the FAQ, since v0.1.7 Claude in T3 Code drains the 5-hour limit at the same rate as Claude Code. Weekly limits were never affected. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)

**ToS:** the FAQ says T3 Code is within the terms of service for Claude Code, Codex and Google Antigravity, and that the team worked directly with the labs on the Grok Build and Cursor integrations. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)

### The Gemini question — the one gap

- **Gemini CLI is NOT a named first-class provider** in T3 Code's provider list (Codex, Claude, Cursor, Grok Build, OpenCode, Antigravity, Kiro, Pi, Muse Code, fx, plus ACP agents). — https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17)
- **But Google replaced the consumer Gemini CLI path with Antigravity:** per Google's announcement, free access for Google AI Pro/Ultra, Gemini Code Assist for individuals and Google One users was discontinued 2026-06-18; "Gemini CLI was replaced by Antigravity CLI on June 18th, 2026." Paid API access, Vertex AI and Code Assist Standard/Enterprise licences are unaffected. — https://innfactory.ai/en/ai-harness/gemini-cli/ (read 2026-11-17); https://www.vibetoolrank.com/compare/codex-vs-gemini-cli/ (read 2026-11-17)
- **Antigravity is a named T3 Code provider**, so the current Google-agent route inside T3 Code is Antigravity, not Gemini CLI. — https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17)
- **The ACP back door:** Gemini CLI speaks the Agent Client Protocol natively (`gemini --acp`; it was the initial ACP reference implementation) and is listed in the ACP Registry, and T3 Code supports "any ACP agent". So Gemini CLI *should* be drivable through T3 Code's ACP support, using a paid Gemini API key / Vertex AI / Code Assist licence for auth. — https://dev.to/gabrielanhaia/agent-client-protocol-by-hand-drive-gemini-acp-over-json-rpc-on-stdio-1jdj (read 2026-11-17); https://agentrq.com/blog/which-coding-agents-support-acp-agent-client-protocol (read 2026-11-17); https://github.com/pingdotgg/t3code (read 2026-11-17)
- **Verdict on Gemini:** **unsure — not verified end to end.** No source I found confirms a working T3 Code + Gemini CLI setup, and the ACP path means you get the protocol's view of the agent, not its native interface. If Gemini matters, test `gemini --acp` through T3 Code before relying on it; the safe assumption is Antigravity, not Gemini CLI.
- **No local models, by design:** FAQ: "T3 Code is a serious developer tool. Locally runnable models are not capable of meaningful engineering work." — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)

## 3. Features for a power user running many agents in parallel

- **Worktrees:** "Git built in. Each thread can work in its own worktree." `t3 thread start ... --worktree` runs a thread in a new git worktree based on a branch, tag or commit, so agent experiments never touch your working tree. Settings → Worktrees → Cleanup offers automatic worktree cleanup (one user reportedly cleared 500 GB of stale worktrees). — https://github.com/pingdotgg/t3code (read 2026-11-17); https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17); https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)
- **Parallel sessions:** threads are the unit of work; many threads run concurrently, each with its own provider/model, and you can switch a thread's provider mid-conversation ("Change models in the middle of a thread. Let Claude hand a task to Codex."). Cross-agent handoff passes a slice of the conversation (16,000 tokens to start by default, per one comparison). — https://github.com/pingdotgg/t3code (read 2026-11-17); https://enjoy.dev/blog/claude-code-and-codex-together/ (read 2026-11-17)
- **Review / diff UI:** review the diff, then commit, push and open a pull request with one button, from the README. The Android app listing describes "pretty much the full power of the desktop app — start agent runs, browse files, do version-control actions, review diffs, and use the terminal." — https://github.com/pingdotgg/t3code (read 2026-11-17); https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17)
- **Remote / phone access:** run `t3 up` on any box and drive it from anywhere — T3 Connect (managed relay, free ≤3 machines), LAN pairing, or Tailscale; web client at app.t3.codes; iOS/Android apps. The phone is a remote: the host does the work and must stay on. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17); https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17)
- **Headless / scriptable use — yes, and this is the strongest fit for a scheduler setup:**
  - `t3 serve` starts the server without opening a browser (what you want headless/over SSH); default port 3773, overridable with `--port` or `T3CODE_PORT`. — https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17); https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17)
  - `t3 service install` registers a systemd user service on Linux (starts at boot, keeps running after logout, with lingering). — https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17); https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17)
  - `t3 thread start <path> "<prompt>" --wait` starts a thread from the terminal and blocks until the agent finishes, printing its reply; exit 1 on failure, 2 if it ends waiting for an answer. Flags: `--worktree`, `--provider`, `--model`. `t3 thread list` / `t3 thread show` / `t3 thread send` cover the rest of the terminal workflow. — https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17)
  - **Scheduled tasks:** built in — recurring agent work on a schedule, plus auto-resume when usage limits reset. Agents can create scheduled tasks themselves via the MCP server. — https://www.growthtrait.com/en/blog/t3-code (read 2026-11-17); https://www.ai-primer.com/engineer/stories/t3-orchestrator-v2 (read 2026-11-17)
  - **Cross-agent orchestration (Orchestrator V2, v0.1.0, 2026-10-15):** `delegate_task` lets one agent spawn child agents on any provider/model and wait for the result; a built-in MCP server lets outside agents (Claude Code, Codex, ChatGPT) launch, message, wait on and stop threads, and manage queues, projects and scheduled tasks. — https://mwolson.org/blog/2026-10-15-t3-code-v0-1-0-orchestration-and-beta/ (read 2026-11-17); https://www.ai-primer.com/engineer/stories/t3-orchestrator-v2 (read 2026-11-17)
  - **Permission modes:** four per thread — Supervised, Auto-accept edits, Auto, Full access. **New threads default to Full access** (no approval prompts) — change the default before pointing it at a real repo. — https://www.developersdigest.tech/blog/t3-code-open-source-gui-claude-code-codex-opencode-2026 (read 2026-11-17); https://aicodewith.ai/en/blog/t3-code-claude-code-codex-setup (read 2026-11-17)
- **Usage/limits in one place:** a usage page combines reported activity across agents and accounts, but cost figures are API-equivalent estimates, not your actual subscription bill. — https://press-report.net/ai-in-technology/need-one-workspace-for-ai-coding-subscriptions-meet-t3-code/ (read 2026-11-17)
- **Caveats for headless use:** the server is a single point of failure in the loop (if it dies, threads die with it unless the systemd service restarts it — **unsure** whether the service auto-restarts on crash; not verified); v0.1.x means breaking changes happen (the v0.1.0 upgrade copied threads one way and required updating every connected server, desktop app and phone app). — https://www.aiagentslist.io/agents/t3-code (read 2026-11-17)

## 5. Recommendation: TRY (for this specific user)

**Profile assumed:** already running Claude Code + Codex CLI headless on Linux, driven by a scheduler; comfortable in a terminal; values reliability over UI polish.

**Try T3 Code — on one box, alongside the existing setup, not instead of it — because:**

1. **It costs nothing and risks no subscription.** Free, MIT, drives the CLIs and logins already in place; Claude Max and ChatGPT Pro keep working. The only new moving part is the `t3` server itself. — https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)
2. **The wins are real and specific to this profile:** (a) phone/web approval and monitoring of agents running on the headless box — the one thing bare CLIs cannot do without SSH; (b) a unified diff/review + one-button PR flow across Claude and Codex threads; (c) `t3 thread start --wait --worktree --provider --model` is genuinely scriptable, so the existing scheduler can drive T3 Code instead of raw CLIs with little rework; (d) cross-agent handoff (Claude plans, Codex implements) and scheduled tasks with limit-reset auto-resume are things a hand-rolled scheduler does not give you. — https://aifrontierpost.com/articles/t3-code-remote-control-coding-agents-tutorial/ (read 2026-11-17); https://mwolson.org/blog/2026-10-15-t3-code-v0-1-0-orchestration-and-beta/ (read 2026-11-17)
3. **Linux is a first-class platform** here, unlike Conductor and Crystal, which are macOS-only (and Conductor is shutting down). — https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md (read 2026-11-17); https://paradev.com/compare/superset-vs-orca-vs-conductor (read 2026-11-17); https://crystl.dev/docs/faq/ (read 2026-11-17)

**Why not "adopt" outright:**

1. **It is v0.1.x beta that says "expect bugs"** — a server in the loop is a new failure mode for unattended scheduled work, and upgrades have been breaking (v0.1.0 required updating every client). Keep the scheduler able to fall back to raw `claude`/`codex` until T3 Code survives a few weeks. — https://github.com/pingdotgg/t3code (read 2026-11-17); https://www.aiagentslist.io/agents/t3-code (read 2026-11-17)
2. **Defaults are unsafe for unattended use:** new threads default to Full access (no approvals), and telemetry is on unless you set `T3CODE_TELEMETRY_ENABLED=false`. Set both before any scheduled run. — https://aicodewith.ai/en/blog/t3-code-claude-code-codex-setup (read 2026-11-17); https://github.com/pingdotgg/t3code/blob/main/docs/user/faq.md (read 2026-11-17)
3. **It does not beat the bare CLIs for unattended work.** For a scheduled job that just runs and reports, `claude -p` / `codex exec` is simpler, has fewer moving parts, and cannot be broken by a T3 server upgrade. T3 Code's edge is supervision, remote control and cross-agent work — all interactive concerns.
4. **Gemini is unresolved** (see §2): if Gemini is a hard requirement rather than a nice-to-have, T3 Code is not yet proven for it; Zed's Agent Panel is the safer bet for Gemini CLI today, since it installs Gemini CLI from the ACP Registry as a matter of course.

**Closest rivals if T3 Code disappoints:** **Claude Squad** (free, AGPL, terminal-native, Linux, any CLI agent including Gemini — the lowest-commitment way to get worktree-parallel agents, though its last push was 2026-08-20) and **Zed** (mature, GPL, Linux, parallel ACP threads including Gemini CLI, but it is an editor first — no phone app, no scheduled tasks). Skip Conductor (shutting down) and Crystal/crystl (macOS only). opencode is worth trying as an *agent*, not as a harness.

**Suggested trial (one evening):** `curl -fsSL https://t3.codes/install.sh | sh` on the headless box → `t3 serve` + `t3 service install` → point the scheduler at `t3 thread start . "<task>" --wait --worktree` for one job class → check it from the phone app via T3 Connect or `t3 up --lan` over Tailscale → decide after a week whether the review UI and remote approvals earn the extra daemon.
