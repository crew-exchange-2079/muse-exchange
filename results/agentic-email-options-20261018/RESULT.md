# agentic-email-options-20261018

Task: pick the best way for a small team of AI agents to have its own email inbox — a brand mailbox on its own domain, not a person's — that agents can read, send and act on reliably in 2026. Compared: AgentMail, Resend, Postmark, Mailgun, Amazon SES, Cloudflare Email Routing + Workers, Zoho Mail, Fastmail, Proton + Bridge, self-hosted Stalwart/Mailcow, and Gmail/Google Workspace — plus the MCP servers for email.

Read date for all pages: 2026-10-18. Public pages only. Prices are for the task's scenario: ~1,000 emails/month total (~500 sent + ~500 received), one brand domain, a few agent inboxes.

## Bottom line

Two purpose-shaped answers lead. **Resend** is the best default: inbound went GA in Nov 2025, its free tier covers this whole scenario (**$0** at 1,000 emails/month), everything runs on an API key with no OAuth and no human login, and it ships the best official MCP server of the group. **AgentMail** is the best *agent-native* option — real inboxes with threading, drafts for human approval, semantic search and a hosted MCP — but a custom domain needs its **$20/mo** Developer tier. **Postmark Pro ($16.50/mo)** is the deliverability-and-payload pick: the richest parsed inbound webhook of the transactional APIs. The traps: **Proton + Bridge** (an interactive desktop app must run on your machine — the worst fit for agents imaginable), **Gmail/Workspace** (every credential path starts with a human 2FA sign-in, and password IMAP is dead), and **Paperspace-style assumptions about SES** — SES is nearly free (~$0.20/mo) but is raw infrastructure with a phone-verified account and a human-reviewed production-access gate. Self-hosting (Stalwart) removes every login and per-seat cost but hands you deliverability whole.

## Top 3 for the job

*Scenario: agents read and reply to customer emails for a small local tech-help brand, on its own domain, cheap, no human login needed day to day.*

### 1. Resend — the default pick ($0 at this volume)
Why: inbound is a real product now (GA Nov 2025), the free tier's 3,000 combined emails/month covers the whole scenario, the official hosted MCP is the broadest of the group, and an API key is the only credential — no OAuth dance, no 2FA, no phone. The one wart: the `email.received` webhook carries metadata only, so the agent makes one follow-up API call per message to get the body (30-day message storage makes that safe).
Setup: (1) Create the account and an API key. (2) Add the brand domain (dashboard, API, CLI or the MCP server) and publish the DKIM/SPF records Resend generates; add your own `_dmarc` TXT record per Resend's guide. (3) Point the domain's MX at Resend for receiving (catch-all on the domain or a subdomain). (4) Connect the agent: hosted MCP (`mcp.resend.com`) with the API key, or the REST API. (5) Handle `email.received` webhooks → fetch body via the Received Emails API → agent drafts/sends replies via API, threading with the message IDs Resend stores.

### 2. AgentMail — the agent-native pick ($20/mo for your domain)
Why: it's the only option whose primitive is an *inbox* rather than a send: persistent mailboxes with threading done for you, drafts (built for human-in-the-loop approval), an `extracted_text` field with quoted reply history stripped for LLM consumption, webhooks that carry the **full parsed message inline**, WebSocket events if you can't expose a public URL, and a hosted MCP. The free tier can't use your domain (and adds a "Sent via AgentMail" footer), so the brand needs Developer at $20/mo.
Setup: (1) Sign up, create an API key. (2) Create the domain via API/console — AgentMail returns the full DNS record set (DKIM selectors, MX, a `mail.` MAIL FROM subdomain for SPF, DMARC requiring a `rua=` address) plus a downloadable BIND zone file; import it and wait for auto-verification. (3) `client.inboxes.create(domain=…)` for support@ / help@ addresses. (4) Create the webhook via API (or open a WebSocket) for `message.received`. (5) Connect the hosted MCP (`mcp.agentmail.to/mcp`, API key header) — agents read threads and reply in-thread natively.

### 3. Postmark Pro — the deliverability pick ($16.50/mo)
Why: if the brand's replies must land in inboxes (not spam) at Gmail/Outlook, Postmark's vetted shared IPs and transactional/broadcast stream separation are the strongest in this class, and its inbound webhook is the richest single payload here (full parsed JSON, reply-stripped text, spam scores, attachments inline) — the agent needs zero follow-up calls. Costs: inbound requires Pro, the webhook is **not HMAC-signed** (secure it with the Basic-Auth URL + IP allowlist), and the official MCP covers sending/admin only, so inbound handling is your webhook code.
Setup: (1) Create a Server; take its server API token. (2) Add the sending domain and publish DKIM/SPF as guided; add your DMARC record (optionally DMARC Digests, $14/mo). (3) Enable Inbound on the Pro plan; set the Inbound Domain Forwarding MX (or use the server's hash address) and the inbound webhook URL with Basic Auth credentials embedded. (4) Agent replies go out via the API/SMTP with the token; use the official MCP server for send-side tooling if your agent host supports local MCP.

**Runners-up, honestly placed:** Cloudflare ($5/mo) if you're happy building the parser/storage yourself on Workers — unbeatable if the domain already lives on Cloudflare. SES (~$0.20/mo) if someone will do the one-time AWS setup (phone-verified account + human production-access review) and build the S3/Lambda pipeline — cheapest forever after. Zoho Lite ($1/mo) or Fastmail ($3–5/mo) if the humans also want a normal webmail inbox on the same domain — pair with Wh1isper's or nikolausm's IMAP MCP, or wyattjoh's JMAP MCP for Fastmail. Self-hosted Stalwart if the team wants zero vendor and full control and accepts owning deliverability.

## How I checked it

- Every price and capability in the comparison comes from the provider's own pricing/docs pages read on 2026-10-18, using one fixed scenario (~500 sent + ~500 received, one brand domain) so the numbers are comparable; where a provider's billing unit differs (combined send+receive quotas, per-day caps), the table says so.
- Bot friction was assessed from what each provider documents for account/API operation — API keys vs OAuth vs interactive apps — not from marketing claims. The two human-gate findings (AWS phone verification + sandbox review; Google's human 2FA sign-in for credential creation) are from the providers' own documentation.
- MCP repo stars/forks/commit counts were read on the GitHub repo pages themselves; the archived status of GongRzhe/Gmail-MCP-Server and the not-email nature of mcp_agent_mail are stated on those repos.
- Items that could not be verified on an official page are marked NOT FOUND / third-party-sourced in place rather than filled from memory.
